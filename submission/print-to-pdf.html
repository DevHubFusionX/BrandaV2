Task 2 — Technical Assessment (50,000 SKUs Storefront)

1. Frontend Architecture for Speed, Scale & Maintainability

  • Domain-Driven Modularity: Feature-grouped Next.js App Router structure (app/(storefront)/shop/, products/[slug]/, lib/commerce/pricing.ts) isolating business logic from UI leaves.
  • Server/Client Boundary Separation: Server Components handle data fetching, metadata generation, and static structural layouts; Client Components are pushed strictly to interactive leaves (swatches, quantity steppers, cart modal).
  • Single Source of Truth (DRY / SOLID): Unified pricing engine (@/lib/commerce/pricing.ts) managing volume discount matrices (MOQ, 25+, 50+, 100+), currency conversions (NGN/USD FX rates), and Nigerian FIRS 7.5% VAT.
  • 50,000 SKU Catalog Scaling: Edge Route handlers with Redis cache, streaming SSR pagination, and multi-facet filtering querying backend indexes rather than shipping monolithic client bundles.

2. Product & Category SEO, Canonical URLs, Structured Data & Indexation

  • Server-Side Metadata: Server Component generateMetadata({ params }) injecting deterministic canonical URLs (https://branda.com.ng/products/[slug]), OpenGraph cards, and descriptive titles before client hydration.
  • Sitemap Chunking: Next.js generateSitemaps() chunking 50,000 SKUs into indexed 10,000-URL sitemaps (/sitemap/0.xml to /sitemap/4.xml), staying strictly within search crawler thresholds.
  • Schema.org Structured Data: Dual-layer JSON-LD script emission: Product with AggregateOffer (lowPrice, highPrice, NGN currency, inStock), coupled with BreadcrumbList schema for Google search rich snippets.
  • Crawl Traps Prevention: robots.ts disallowing query permutations (/*?*q=*, /*?*sort=*, /checkout/, /cart/) to conserve Googlebot crawl budget exclusively for canonical department hubs and products.

Task 2 (Continued) — Performance, Resilience & Code Quality

3. Minimizing JavaScript, Layout Shifts (CLS), API Waste & Slow Pages

  • Zero CLS Guarantee: Pre-allocated aspect-ratio containers (aspect-square, aspect-[4/3]) with CSS skeleton streams preventing content re-flow during API hydration.
  • Bundle Pruning: Replaced monolithic component UI libraries with zero-runtime Tailwind CSS and tree-shaken SVG icon modules (lucide-react). Dynamic imports (next/dynamic) for heavy 3D proof and payment modals.
  • Sub-50ms TTFB via Edge Caching: Product pages cached with ISR (revalidate: 3600) and stale-while-revalidate HTTP headers. Live search debounced (300ms) with SWR/React Query caching to prevent backend request storms.
  • Real User Monitoring: Integrated useReportWebVitals telemetry reporting LCP, CLS, and INP metrics directly to telemetry beacons, paired with a non-intrusive in-app performance HUD.

4. Cart, Checkout, Authentication, API Failures & Loading States

  • Optimistic State Management: Zustand persistent cart synchronized via localStorage with optimistic UI updates for instant stepper increments and removals across tabs.
  • Graceful Degradation & Circuit Breakers: Next.js API proxy routes implementing resilient circuit-breaker patterns: in the event of third-party API rate-limiting or network downtime, the system automatically falls back to curated local catalog items without user disruption.
  • Granular Boundary Ergonomics: Isolated loading.tsx skeletons and error.tsx boundaries isolating component exceptions and offering instant retry buttons without crashing parent navigation.
  • Dual-Path Commercial Checkout: Engineered a frictionless 2-stage B2B purchasing flow:
    • Stage 1: Free Digital 3D Mockup Request (no card required upfront, matching enterprise procurement).
    • Stage 2: Test Mode Production Deposit Gateway (simulating Paystack card & virtual bank transfer with 3D Secure OTP verification and FIRS VAT compliance).

5. Junior Developer Code Reviews & Production Bug Prevention

  • Automated CI/CD Guardrails: Husky pre-commit hooks enforcing TypeScript compilation (tsc --noEmit), ESLint rules, and Vitest/Jest pricing test suites before code enters Git.
  • Review Checklist Standards:
    • Server/Client Boundaries: Enforcing `'use client'` only at interactive leaves.
    • SEO & Accessibility: Verifying semantic HTML, ARIA labels, image alt tags, and canonical tags.
    • DRY & Single Source of Truth: Guaranteeing zero duplicated pricing math outside @/lib/commerce/pricing.ts.
  • Staging Assertions: Ephemeral preview deployments on every PR with automated Lighthouse CI gates (blocking any PR resulting in Mobile Performance < 90 or SEO < 95).
